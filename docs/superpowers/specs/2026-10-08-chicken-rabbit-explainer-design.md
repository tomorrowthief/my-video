# 鸡兔同笼讲解视频 — 设计

日期：2026-10-08
状态：已评审通过，待实现

## 目标

做一支约 3 分钟的小学数学讲解视频，题目是鸡兔同笼。要讲到的不是「答案是多少」，
而是「同一道题的三种解法其实是同一句话」。

受众是小学生，旁白用第二人称、短句、先问再答。数学深度不打折扣。

成功标准：

- 看完的人能独立解出片尾留的变形题（自行车三轮车），而不是背住 `差÷2` 这个公式
- 三种解法的画面语言各不相同，不是同一个式子换三种配色
- 两支视频（pi-durable、本片）在同一个仓库里共存，互不干扰

## 题目与答案

笼子里有鸡和兔共 **35** 只，脚共 **94** 只。鸡和兔各有几只？

答案：鸡 **23** 只，兔 **12** 只。

验算：`23 + 12 = 35`，`23 × 2 + 12 × 4 = 46 + 48 = 94`

## 内容结构

六幕。下面每幕标的秒数是**目标**，不是写死的值 —— 实际时长由 TTS 生成的 wav 决定
（见「时间轴是音频决定的」）。按 40 句、语速 165 估算，成片大概落在 2 分半到 3 分半之间。
如果总时长明显偏离，调旁白句子的多少，不要去改场景里的帧数。

### S0 出题（~25s）

笼子、35 个头、94 只脚。念完题目后**停一拍**让观众自己猜 —— 这一拍是故意留的，
后面每一种解法的说服力都建立在观众先体验过「猜不出来」。

画面：头和脚分两行点阵，数字咬合。

### S1 列表法（~35s）

最笨的办法：一个一个试。

| 鸡 | 兔 | 脚 |
|---|---|---|
| 35 | 0 | 70 |
| 30 | 5 | 80 |
| 25 | 10 | 90 |
| 23 | 12 | **94 ✓** |

**这一幕的目的不是解题，是让观众自己发现「每多一只兔，脚多 2 只」。**
后面两种解法都站在这个规律上。如果跳过这一幕直接教假设法，孩子只会背公式。

画面：表格逐行填充，脚数条逼近 94 刻度线。

### S2 假设法（~40s）

先假设全是鸡：`35 × 2 = 70`。实际 94，**差 24**。
每把一只鸡换成兔，脚数 +2，所以兔 = `24 ÷ 2 = 12`，鸡 = `35 − 12 = 23`。

画面：35 个暖黄圆点，脚数 70 对照 94，缺口橙色闪动，然后两只脚两只脚地补上去，
对应的头从鸡色渐变为兔色。

### S3 抬腿法（~40s）

吹一声哨，所有动物抬起两只脚。抬起 `35 × 2 = 70` 只，
地上还剩 `94 − 70 = 24` 只。鸡只有两只脚、全抬起来了，所以地上这 24 只脚全是兔子的后腿。
`24 ÷ 2 = 12` 只兔。

画面：所有动物同时抬腿（整齐的位移动画），地上剩下的脚两两配对。

### S4 三解合一（~30s）

**这一幕是全片的点，不是总结。**

三种解法并排收敛到中间一行字：

- 列表法 —— 试出了一个规律
- 假设法 —— 直接用这个规律
- 抬腿法 —— 把这个规律变成一个动作

内核是同一句话：**一只兔子，比一只鸡多两只脚。**

### S5 验算 + 留题（~20s）

两条验算打勾。然后抛变形题：自行车和三轮车共 10 辆、轮子共 26 个，各有几辆？

（答案：自行车 4、三轮车 6。`4 × 2 + 6 × 3 = 26`）

**这道变形题每换一辆轮子只多 1 个，不是 2 个。** 选它是因为背公式的人会在这里翻车，
真懂了的人不会 —— 片尾旁白明确提醒这一点，把「理解」和「记住」分开。

## 视觉设计

沿用现有 `Stage` 的深色底和网格（类 3Blue1Brown 的电影感），换一套暖调配色。

| 角色 | 颜色 | 形状 |
|---|---|---|
| 鸡 | `#f5c35a` 暖黄 | 圆形 |
| 兔 | `#b79bff` 淡紫 | 圆角方形 |
| 关键数字 / 缺口 | `#ff8f4a` 橙 | — |
| 底色 | `COLORS.bgDeep` | — |

鸡兔用**形状 + 颜色双重区分**，不只靠颜色 —— 色盲友好，且在动画中形状变化比色相变化更易读。

新增的颜色放进 `src/theme.ts` 的一个独立导出（如 `MATH_COLORS`），不污染 `COLORS`。

## 技术架构

### 核心约束

现有 `scripts/tts.mjs` 会 `rmSync(public/audio)` 再覆写 `src/timing.json`。
直接跑第二支视频会删掉 pi-durable 的全部素材。**必须先把素材按视频分家。**

### 文件布局

```
narration/pi-durable.json          （从仓库根的 narration.json 移入）
narration/chicken-rabbit.json      新增

src/timing/pi-durable.json         （从 src/timing.json 移入）
src/timing/chicken-rabbit.json     新增

public/audio/pi-durable/*.wav      （从 public/audio/ 移入）
public/audio/chicken-rabbit/*.wav  新增
```

### 改动清单

| 文件 | 改动 |
|---|---|
| `scripts/tts.mjs` | 收一个 slug 参数（`node scripts/tts.mjs chicken-rabbit`），读 `narration/<slug>.json`，写 `public/audio/<slug>/` 和 `src/timing/<slug>.json`。只清理自己那个 slug 的目录，不碰别人的。 |
| `src/components/Stage.tsx` | 已有未提交改动把 `brand` / `audioDir` 变成可传参数 —— 保留，提交。 |
| `src/PiDurable.tsx` | 改 import 路径指向 `src/timing/pi-durable.json`，显式传 `audioDir="audio/pi-durable"`。 |
| `src/theme.ts` | 新增 `MATH_COLORS` 导出。 |
| `src/ChickenRabbit.tsx` | 新增。结构照抄 `PiDurable.tsx`：按 `timing.json` 的绝对帧摆六个 `Sequence`。 |
| `src/scenes/math/M0…M5*.tsx` | 新增六个场景组件，放在 `src/scenes/math/` 子目录下，和 pi-durable 的场景分开。 |
| `src/Root.tsx` | 新增 `Folder name="Math"` + `ChickenRabbit` composition。 |

### 为什么这样分

`Stage` 已经把 Backdrop / SceneHeader / Caption / ProgressBar / Narration 这五件事封装好了，
并且 `brand` 和 `audioDir` 都可传参。场景组件只需要关心 `top: 132` 到 `bottom: 148`
之间那块内容区，拿到的输入是 `scene: SceneTiming`，用 `useSceneFrame` 得到当前第几句、
句内第几帧。这个边界是干净的：场景不知道字幕长什么样，`Stage` 不知道场景画了什么。

被否掉的两个方案：

- **完全独立**（新建 `src/chicken/` 带自己的 Stage）：Backdrop / Caption / ProgressBar 整份复制，
  以后改字幕样式要改两处。
- **单文件内联**（六幕挤一个文件）：写起来快，但 190 秒的动画逻辑在一个文件里无法单独调某一幕。

### 时间轴是音频决定的

`timing.json` 由 `tts.mjs` 从真实 wav 时长算出，场景按绝对帧摆放。
这意味着**改旁白文案就会自动重新剪辑整支片子** —— 场景组件里不能写死「第 90 帧出现」这种数字，
一切时间都要从 `scene.paragraphs[i].startFrame` / `durationInFrames` 推导。

语速：`rate: 165`（pi-durable 是 183，对小学生偏快）。

## 旁白脚本

`say` 是念出来的（口语、可以长），`show` 是屏幕字幕（精炼）。配置：

```json
{ "voice": "Tingting", "rate": 165, "gapSeconds": 0.42, "leadInSeconds": 0.55, "tailSeconds": 1.05 }
```

`gapSeconds` 比 pi-durable 的 0.32 更长，给小学生留反应时间。

## 动画要点

每一幕的时间都从 `scene.paragraphs[i]` 推导，用 `since()` / `easeOut()` / `easeInOut()`
这三个现成的工具函数，不要引入新的缓动约定。

| 幕 | 关键动画 |
|---|---|
| S0 | 35 个头依次弹入（stagger），脚的点阵在念到「94」时成批铺开 |
| S1 | 表格逐行写入；右侧脚数条随行变化，94 处有一条固定刻度线，最后一行命中时刻度线发光 |
| S2 | 35 个暖黄圆点铺满 → 脚数条停在 70 → 94 的缺口橙色脉冲 → 逐对补脚，对应头从黄渐变成紫圆角方 |
| S3 | 所有动物同时向上位移两只脚（`easeInOut`），地面线以下只剩兔腿 → 两两配对高亮计数 |
| S4 | 三列并排 → 向中间收敛（位移 + 透明度）→ 中间一行字放大定格 |
| S5 | 两条验算从左到右写出，末尾打勾；变形题淡入 |

## 测试与验收

这是视频项目，没有单元测试可写。验收靠：

1. `npm run lint`（`eslint src && tsc`）必须过
2. `npx remotion studio` 打开 `ChickenRabbit` composition，逐幕看一遍
3. **`PiDurable` composition 必须仍然正常播放** —— 素材分家后的回归检查，这一条最容易出错
4. 抽帧截图检查：每幕取中间一帧，确认没有文字溢出、没有元素重叠

## 风险

| 风险 | 处理 |
|---|---|
| 素材分家时弄坏 pi-durable | 先用 `git mv` 移动文件并提交，再改代码，分两步；每步后都在 studio 里验证 `PiDurable` |
| 旁白重新生成后时长变化导致排版错位 | 场景组件不写死帧数，一切从 `scene.paragraphs[i].startFrame` 推导 |
| 35 个头 + 94 只脚在 1920×1080 内排不开 | 脚用小圆点分行密排，不画写实的腿；S0 的脚点阵可以分两行各 47 个 |
| macOS `say` 把「九十四」念成别的 | 旁白里数字一律写成中文汉字，不写阿拉伯数字；生成后听一遍 |
